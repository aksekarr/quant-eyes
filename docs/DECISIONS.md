| 2026-09-28 | Engine foundation conventions (METHODOLOGY.md section 1): series matched by calendar month; any gap, duplicate, zero, negative or non-numeric value rejects the series; nothing under 12 months is annualised; the engine never rounds; error messages never show a value. | Fail closed rather than guess; one rounding per displayed number; raw values never reach logs. |
| 2026-09-28 | Volatility uses the sample standard deviation (divide by n − 1), annualised by x sqrt(12). | The convention in Excel STDEV.S and pandas, and what an independent cross-check will assume. |
| 2026-09-28 | Every comparison with the tracker uses identical months (the common window). | 2026-09-28 | Largest-fall conventions (METHODOLOGY.md section 3.2): measured at month-end; the first month counts as a high; on a tie the earliest trough; the peak is the last month at the high; recovery means back at or above the peak; underwater is elapsed months from peak to recovery; the £ figure applies only to £10,000 invested at the high; an unrecovered fall is stated as "not recovered by [month], still X% below its high", never as a forecast. | Each is a place where a plausible-looking number could mislead; fixing them in writing makes the card checkable. |
| 2026-09-28 | Stress-window and holding-period conventions (METHODOLOGY.md section 4): a window is covered only if both its end months exist, never shortened; a window's return is described as "over the period", not as a fall; N month-end values give N − h holding periods of h months, of which (N − 1) ÷ h (rounded down) do not overlap; horizons are whole years; ties go to the earliest start; "lost money" means below zero; totals and per-year figures are both computed and the display choice is made later. | Fence-post and overlap errors are the easiest way to overstate the evidence; fixing the definitions makes the card checkable. |
| 2026-09-28 | 90/10 comparison: starts at 90% tracker / 10% asset in the first month of the common window, rebalanced to 90/10 at the end of every December, before fees, no trading costs or tax. Correlation and 90/10 conventions as METHODOLOGY.md section 5 (same currency and basis required; Pearson on monthly returns; rolling 36-month range; the mix's value line is internal only). | Every December is the easiest rule to state in plain English and gives every asset the same rebalancing dates. |
| 2026-09-28 | Engine output (METHODOLOGY.md section 6): one function returns everything; each card has an "own" view (the asset's full history in pounds) and a "side by side" view (asset and tracker over identical months); dollar assets get the currency split over the full history and each stress window; total-return series only (price-only refused); every output carries a method version; a fixed-shape allowlist in which the only list is the three stress windows, checked by the engine before returning. | One door out of the engine, with a shape that cannot carry a price series, and a version so every published number can be traced to the method that produced it. |
| 2026-09-28 | As-of month: one per run, the last complete calendar month before the run date. One date across the site keeps every side-by-side comparison on identical months. |
| 2026-09-28 | Month-end picking (METHODOLOGY.md section 7): the latest-dated row in each calendar month; it must fall in the last 7 calendar days of its month or the run fails; only month-end values are read; dates are taken as written, with no time-zone conversion. Tiingo is fetched daily and Alpha Vantage monthly, and the same rule applies to both. | A lagging provider or a month missing its last days would otherwise pass silently as a month-end value. One rule for every source; Tiingo's monthly resample labelling is not documented. |
| 2026-09-28 | Bitcoin's first value is the end of Dec 2014, so its first monthly return is Jan 2015. | Same fence-post convention as the stress windows ("measured from the month-end before"). |

| 2026-09-29 | Headline read: OpenAI `gpt-6.1-sol` drafts it at build time, run by Avi with a key for this project only (its only permission: model requests) and a hard monthly spend limit ($5). | 2026-09-30 | Headline drafting (METHODOLOGY section 15.3): the model is given only the page's own cards 1 to 3 sentences whose figures are all the asset's observed history, and the response format lets it cite only those figures; one attempt per asset, no automatic retry; `store: false`, reasoning effort fixed at medium, at most 8,000 output tokens a request; all drafts with their problems go to `words/headline_drafts.json`, committed as the record of what the model proposed; Avi can redraft only the assets he names. | 2026-09-30 | Headline method amended after review of the first real drafts (all 7 passed the checker; 6 were rejected): superlatives (largest, biggest, worst, deepest, steepest, sharpest, greatest, highest, lowest, record, ever, all time) are loaded words, so a headline dates a fall and never ranks it; the model is never offered `worst.months_to_recover`, so time to recover is always counted from the high; prompt version 2 adds that rule (wording approved by Avi). The rejected drafts are committed as the first entry in the drafts record. | Our data starts at a fixed month (2005 to 2014), so an unqualified "largest fall" is an all-time claim the data can't support: bitcoin and the US shares fell further before their windows. From-the-low recovery time is the flattering figure, and mixing the two measures reversed a comparison between pages. Banning the words and removing the figure are structural; an instruction alone would be a request. |
| 2026-09-30 | Headline method amended again after review of the second drafts: on a page for an asset that trades in dollars (Microsoft, Apple, Nvidia, bitcoin), a cited figure in pounds needs the words "in pounds" and one in dollars "in dollars" (METHODOLOGY section 15.1 rule 16); prompt version 3 tells the model so, with an input line for a dollar asset (wording approved by Avi). | Every figure on a page is in pounds.
